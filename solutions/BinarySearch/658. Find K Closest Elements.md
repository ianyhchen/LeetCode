# LeetCode 658. Find K Closest Elements 筆記

## 1. 題目解析
- 給定排序陣列 `arr`，找距離 `x` 最近的 `k` 個連續元素。
- 距離定義：優先取差值絕對值小者；若絕對值相等，取數值小者。
- 關鍵：利用「排序」特性，目標區間必然是連續子陣列。

## 2. 核心演算法與資料結構
- **演算法**：二分搜尋 (Binary Search)
- **目標**：尋找長度為 `k` 的區間之「左邊界索引值」。

## 3. 解題思路：二分搜尋左邊界 (Binary Search for Range Start)
- **範圍**：初始化 `low = 0`, `high = len(arr) - k`。
- **判斷條件**：
  比較 `x` 距離區間左側外的元素 `arr[mid]` 與區間右側外的元素 `arr[mid + k]`。
  - 若 `x - arr[mid] > arr[mid + k] - x`，表示 `mid` 離 `x` 太遠，左邊界必在右側：`low = mid + 1`。
  - 否則，左邊界可能在 `mid` 或左側：`high = mid`。
- **優點**：時間複雜度 $O(\log(n-k))$，空間複雜度 $O(1)$。

## 4. 實作細節：為什麼使用 while low < high？
- **搜尋本質**：此解法是在「排除」不可能的左邊界，而非尋找單一特定數值。
- **終止狀態**：當 `low == high` 時，搜尋區間縮小到只有一個點，該點即為最優區間的起點。
- **避免死迴圈**：使用 `low < high` 搭配 `high = mid` 與 `low = mid + 1` 可以確保每次區間都在縮小，且最後精確停在目標索引。
- **比較對象**：比較的是 `arr[mid]` 與 `arr[mid + k]`，這是在評估「向右移動視窗」是否會得到更好的結果。

## 5. 常見錯誤與陷阱
- **搜尋邊界**：`high` 必須設為 `n - k`，確保 `mid + k` 不會越界。
- **比較細節**：不需使用 `abs()`，直接利用 `x - arr[mid]` 與 `arr[mid + k] - x` 比較更簡潔。
- **回傳值**：最後回傳的是 `arr[low : low + k]`。
