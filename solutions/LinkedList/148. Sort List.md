# LeetCode 148. Sort List

## 1. 題目解析
*   **目標**：給定一個鏈結串列（Linked List）的頭部節點 `head`，將其按 **升序** 排列並回傳排序後的串列。
*   **關鍵限制**：
    *   時間複雜度：$O(n \log n)$
    *   空間複雜度：$O(\log n)$ (遞迴棧空間) 或 $O(1)$ (迭代法)。

## 2. 核心演算法與資料結構
*   **資料結構**：`Singly Linked List`。
*   **演算法**：`Merge Sort` (合併排序)。
    *   **Divide (分割)**：利用快慢指標找到中點。
    *   **Conquer (遞迴)**：遞迴排序左右兩半。
    *   **Combine (合併)**：合併兩個有序串列。

## 3. 解題思路與方法比較
### 方法：自頂向下合併排序 (Top-down Merge Sort)
1.  **Base Case**：若節點數量為 0 或 1，代表已排序，直接回傳。
2.  **Split**：使用 `slow` 與 `fast` 指標。初始 `fast = head.next` 是為了在節點長度為 2 時，能讓 `slow` 停在第一個節點，成功將串列切為 1+1。
3.  **Recursion**：斷開 `slow.next`，將原串列拆成 `head` 與 `mid` 兩部分，分別遞迴。
4.  **Merge**：使用 `dummy node` 作為輔助，依序比較兩串列節點值並串接。

| 方法 | 時間複雜度 | 空間複雜度 | 優點 | 缺點 |
| :--- | :--- | :--- | :--- | :--- |
| **Top-down** | $O(n \log n)$ | $O(\log n)$ | 邏輯直觀，實作簡單 | 需消耗遞迴棧空間 |
| **Bottom-up** | $O(n \log n)$ | $O(1)$ | 空間效率最優 | 實作極其複雜，需手動處理節點連接 |

## 4. 常見錯誤與陷阱
1.  **無窮遞迴**：若 `fast` 初始化為 `head` 且串列長度為 2，`slow` 會停在第二個節點，導致 `slow.next = None` 切分後的左半部依然長度為 2。
    *   *解法*：設定 `fast = head.next`。
2.  **忘記切斷連結**：找到中點後必須執行 `slow.next = None`，否則遞迴時會一直處理原始長度的串列。
3.  **收尾處理**：合併時若其中一個串列已空，記得將 `curr.next` 接向另一個非空串列。
